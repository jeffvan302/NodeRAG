# NodeRag 1.0.0-rc.1 Release Notes

## Status

This is a private, x86_64 testbed release candidate. It is not DSM-certified and is not the
NodeRag 1.0.0 production release. Keep `releaseAuthorized=false` until the exact candidate passes
the final live Synology checklist.

## Included capability

- Private PostgreSQL 17.11 with pgvector 0.8.6, reached only through a package-owned Unix socket.
- Local Qwen3-Embedding-0.6B inference with a pinned 1,024-dimension model manifest.
- TXT, Markdown, PDF, DOCX, and XLSX ingestion with normalized canonical Markdown and dual UTF-16/
  UTF-8 locators.
- Recoverable Ollama vision for embedded images and scanned PDF pages.
- Silo-scoped vector, keyword, and hybrid search through the UI, REST, MCP, and narrowed gateways.
- Independent read, upload, delete, reindex, source-configuration, and administrative controls.
- Durable jobs, watched sources, missing-source review, explicit purge, and zero-downtime rebuilds.
- Encrypted full and portable backups, staged restore, same-major upgrade safety, and rehearsed
  PostgreSQL-major rollback.
- Operator UI, health, audit, evaluation, storage, model, job, rebuild, and recovery diagnostics.

## Fixed for this candidate

- The production launcher now supplies the bundled `pg_dump` path to both API and worker recovery
  runtimes, so packaged backups do not depend on a host executable search path.
- Full backups now exclude only transient rebuild relations that are both strictly named and owned
  by recorded NodeRag build state; unreferenced lookalike tables still fail classification closed.
- Restore activation clears non-active rebuild staging/rollback references and fails interrupted
  build/cleanup work for explicit operator review instead of retaining unusable ephemeral state.
- Runtime, API, MCP, package metadata, OpenAPI, settings defaults, parser revisions, dependency
  lockfile, migration head, SBOM, notices, model manifest, and build recipe are frozen together.
- The exact SPK has a minimum 24-hour fail-closed soak runner with source schedules, backup,
  isolation, locator, restart, log, health, memory, storage, and Ollama recovery checks.

## Runtime baseline

- DSM target: x86_64, DSM 7.2 build 64570 or newer.
- Package dependency: Synology `Node.js_v22`.
- CI/test runtime: Node.js 22.22.0 and pnpm 11.25.0.
- Node 22 support was reviewed on 2026-09-04 against the official Node.js release schedule; its
  planned end-of-life is 2027-04-30.

## Upgrade and compatibility

The candidate uses forward-only migration head `000011_recovery_hardening`. Always create and
independently verify a full backup before upgrade. A PostgreSQL-major change is never an in-place
binary swap: use the documented logical dump, new-cluster restore, verification, activation, and
retained-source rollback procedure.

## Known release boundary

Docker/WSL qualification cannot prove Package Center variables, DSM package-account ACLs, the
Synology Node/C++ ABI, real `/volumeN` behavior, Hyper Backup integration, DSM reboot ordering,
NAS thermals, or file-sharing responsiveness. Those remain release blockers in the final DSM
checklist. A DSM failure requires a new release candidate; it must not be waived into `v1.0.0`.
