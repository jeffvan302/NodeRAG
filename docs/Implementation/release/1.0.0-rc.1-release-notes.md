# NodeRag 1.0.0-rc.1 Release Notes

## Status

This is a private, x86_64 testbed release candidate. It is not DSM-certified and is not the
NodeRag 1.0.0 production release. Keep `releaseAuthorized=false` until the exact candidate passes
the final live Synology checklist.

## Included capability

- Private PostgreSQL 17.11 with pgvector 0.8.6, reached only through a package-owned Unix socket.
- Local Qwen3-Embedding-0.6B inference with a pinned 1,024-dimension model manifest.
- TXT, Markdown, PDF, DOCX, and XLSX ingestion with normalized canonical Markdown and dual UTF-16/
  UTF-8 locators.
- Recoverable Ollama vision for embedded images and scanned PDF pages.
- Silo-scoped vector, sentence-refined semantic, keyword, and hybrid search through the UI, REST, MCP, and narrowed gateways.
- Independent read, upload, delete, reindex, source-configuration, and administrative controls.
- Durable jobs, watched sources, missing-source review, explicit purge, and zero-downtime rebuilds.
- Encrypted full and portable backups, staged restore, same-major upgrade safety, and rehearsed
  PostgreSQL-major rollback.
- Operator UI, health, audit, evaluation, storage, model, job, rebuild, and recovery diagnostics.
- Owner-isolated durable Chat with Ollama Cloud generation and internet search/fetch, optional
  OpenAI OAuth generation, Research/RAG tools, citations, safe Markdown artifacts, DOCX/PDF export,
  and verified managed-context archives. For Chat, Ollama never means a local or custom endpoint.

## Fixed for this candidate

- Package revision 46 is the Chat-capable Synology test candidate. It supersedes revision 45 after
  making the Linux/x86_64 SBOM byte-identical across Windows and Linux generation and restoring the
  isolated thin-package lifecycle simulator while preserving strict real-DSM runtime checks. It
  also drains the last managed-context lease heartbeat before shutdown so database teardown cannot
  leave an unhandled connection, and makes each soak obtain its setup key through the install wizard
  after replacing the named disposable volume. It retains revision 45's managed-context concurrency and PDF Research-loading fixes. Arrow-key page
  movement requested during loading is retained and clamped to the real page count when the document
  opens. All exact-artifact gates are repeated against revision 46. Migrations 000019–000029
  add encrypted provider administration, durable owner-isolated runs, Research and RAG tools,
  Ollama Cloud web search/fetch, contained Markdown artifacts, deterministic DOCX/PDF export, and
  managed-context archives/reconciliation. Chat fixes Ollama to `https://ollama.com`; generation,
  web search, and web fetch share the encrypted Ollama Cloud API key while retaining independent
  health and enablement. It also adds Chat Health diagnostics, full Chat backup/restore, safe
  in-flight recovery, feature-disabled rollback, a conversation evaluation catalog, package-user
  lifecycle coverage, and a revision-26 forward-upgrade qualification path.
  Migration `000029_chat_files` also adds private image uploads for each chat. Files receive UUIDs
  independent of their original names and stable DSM-aware addresses such as
  `/noderag/chat/<chat-id>/file/<file-id>.png`. The artifact drawer can copy the URL or a Markdown
  image reference; duplicate original filenames do not collide, managed Markdown loads these
  same-origin images, and ownership, signature, extension, quota, backup, and deletion checks apply.

- Version 1 is scoped to trusted-LAN access through the Synology Web Station `/noderag/` alias.
  Public/WAN access, external DNS, certificate management, and internet-facing reverse proxies are
  not part of this release candidate.

- Package revision 26 fixes a Settings-page state error that initialized both processing sliders to
  1 when an administrator returned from another Administration section. Each settings request is
  now bound to the section and refresh that produced it, so data from Logs, Storage, or another tab
  cannot initialize the resource controls. The update endpoint also returns the saved settings in
  the same camel-case contract as the read endpoint. A browser regression test saves distinct
  embedding and ingestion values, leaves Settings, returns, and verifies both saved values.

- Package revision 25 makes Administration → Settings resource controls operational. The UI reports
  detected logical processors, active and selected embedding threads, offers Responsive, Balanced,
  and Fastest highlights profiles, and bounds sliders to available hardware. Saving a changed thread
  count sends a priority-zero control request over the private embedder socket; the engine finishes
  its active request, releases the ONNX session, and reloads lazily with the new thread count without
  restarting the NAS. The saved value is also restored by the Synology service script. Background
  document concurrency now follows the saved ingest-worker limit, bounded by available processors.
  When interactive priority is enabled, background work cannot take the reserved interactive CPU
  slot, while search and semantic-highlight requests retain priority over queued ingestion work.

- Package revision 24 fixes a PDF viewer regression where an existing semantic sentence on a search
  result could incorrectly suppress the background evidence request even when that sentence could
  not be aligned with the cited page. Every non-keyword PDF view now refreshes semantic evidence,
  including Semantic search results, while retaining any immediately usable ranked evidence. The
  response may return up to four qualifying sentences. The viewer reports whether semantic
  processing is unavailable, no sentence passed the confidence threshold, or qualifying evidence
  could not be aligned to the current PDF page instead of failing silently.

- Package revision 23 separates exact and semantic PDF-highlight timing. Query words and common
  inflections can draw as yellow highlights as soon as PDF.js extracts the cited page's text;
  semantic sentences continue in the background and appear in green when ready. PDF text-layer
  extraction no longer waits for the high-resolution canvas render, and arriving evidence no
  longer restarts that render. A bounded 24-hour cache keys semantic evidence by normalized query,
  passage content, immutable model manifest, prefixes, dimensions, token limit, and confidence
  calibration. Concurrent identical requests share one calculation and failures are not cached.

- Package revision 22 refreshes and merges sentence evidence whenever a PDF search result opens,
  reconstructs fragmented PDF text more accurately, and tolerates line wrapping, hyphen variants,
  ligatures, and token-level semantic alignment when drawing yellow exact and green semantic
  highlights. Research can now save or remove the currently displayed PDF page with the toolbar or
  `0` key, including pages reached after leaving the original cited page. Each page is stored as an
  independent reference with its own page locator and extracted page text. Migration
  `000018_research_page_references` preserves passage-level uniqueness while adding page-level
  uniqueness.

- Package revision 21 adds Administration → Logs, an automatically refreshed view of the newest
  ingestion events from a rolling 24-hour window. It includes document, knowledge space, job stage,
  attempt, page progress, error class, safe database table/constraint diagnostics, and expandable
  technical detail without exposing credentials. PDF layout coordinates are now clipped as a whole
  rectangle before storage, preventing out-of-page glyph coordinates from violating the
  `document_block` bounds constraint after an otherwise successful extraction. PostgreSQL check
  violations are classified as permanent so deterministic save failures do not repeat the entire
  PDF five times. Migration `000017_ingestion_log_window` adds the recent-event index.

- Package revision 20 uses `minimax-m3:cloud` as the default vision model with two parallel calls,
  three images per call, a 120-second timeout, three attempts, and a 1650-pixel maximum image
  dimension. When an encrypted Ollama credential is already configured, submitting the settings
  form with an empty API-key field now decrypts and reuses that credential for the live provider
  test instead of sending an unauthenticated request. Forward-only migration
  `000016_vision_configuration_defaults` updates untouched older defaults while preserving custom
  model and non-default tuning values.

- Package revision 19 adds the four-stage layout-preserving PDF enhancement. New PDFs use
  deterministic native structure first, confidence-routed bounded crops for uncertain regions, and
  full-page vision only for unreadable pages. Strict layout-block responses, crop-policy-aware
  caching, non-duplicating reconciliation, extraction diagnostics, estimates, and transactional
  enhanced re-index chunk swaps are implemented under migration head `000015_pdf_hybrid_vision`.
  PDF diagnostic, vision-estimate, and enhanced re-index-estimate reads now apply the authenticated
  knowledge-base scope inside their database transaction, preventing valid documents from being
  incorrectly reported as not found under DSM's restricted runtime role. This remains a private
  test candidate and is not represented as DSM-certified capability.

- Package revision 18 brings the rich Markdown reader to search results. Native Markdown and text,
  plus canonical Word/Excel extraction, open directly at the best matching cited block with the
  result confidence visible. Right/Left scroll forward and back through the document; Down/Up move
  through displayed results while restoring each citation's original location and automatically
  switching between Markdown and PDF readers when needed. A single modal toggles between the
  rendered document and neighboring source passage, and repeated results from one document reuse
  the already loaded Markdown.
- Package revision 17 replaces the raw canonical-Markdown text box with a responsive document
  reader. Preview mode renders GitHub-style structure, tables, task lists, blockquotes, inline and
  fenced code, and Mermaid diagrams; Markdown source remains one click away and can be copied.
  Raw HTML cannot execute, relative resources are not fetched, external images are opt-in, and
  sanitized diagram output is displayed through an isolated image. Diagrams load only when a
  preview contains them, preserving the ordinary application startup path.
- Package revision 16 corrects large-document embedding progress. Cache inspection can no longer
  leave a stale chunking count such as 491/491 on an active embedding job. The queue separately
  reports newly embedded, cache-reused, and remaining passages, the active passage range,
  measured passages per minute, and an ETA based on remaining embedding tokens. Model calls begin
  in two-passage groups and adapt toward a roughly 20-second update interval, bounded from 1–16;
  a 20-second progress pulse keeps the durable worker lease healthy while a slow call is active.
  Each completed group is committed to the embedding cache immediately, so an automatic retry
  resumes rather than regenerating those vectors. Extraction-quality checks retain all content but
  warn about repeated lines, corrupt characters, symbol-heavy extraction, and token-dense passages.
- Package revision 15 replaces the raw internal-job list with one document-processing row per
  document. Every row advances through 1/3 Markdown ingestion, 2/3 chunking, and 3/3 embedding;
  each stage has its own zero-to-100 progress range and current-task text. The first normal attempt
  is no longer presented as a retry. Actual retries identify the affected stage, next attempt, and
  reason; overdue heartbeats explain automatic worker recovery. Input-folder scans are listed
  separately, while successful and cancelled history is hidden by default and remains available
  through Show finished. Durable job and diagnostic history is not deleted.
- Package revision 14 batches image understanding without confusing batch size with concurrency.
  Administrators can set 1–16 images per provider call beside the parallel-call limit, with a
  default of 5; the connection test validates the selected batch size, and PDF, Word, and Excel
  extraction preserve image/result order. The live ingestion queue now names the document and
  source-relative path being processed, or the input folder for a crawl job.
- Package revision 13 turns each connected input-folder entry into an operational control. An
  authorized user can queue an immediate crawl, edit include/exclude patterns, change or clear the
  repeat interval, and disconnect the source with an explicit retention warning. Disconnecting
  never modifies the external folder and retains managed document copies as searchable detached
  records.
- Package revision 12 canonicalizes and opens an input folder before saving it, maps Synology ACL,
  missing-path, invalid-pattern, and duplicate-source failures to specific UI messages, and retains
  a request reference for any unexpected storage failure. Supplying a repeat interval now enables
  the source schedule and assigns its first due time; earlier revisions stored the interval while
  incorrectly leaving the schedule disabled.
- Package revision 11 moves first-start embedding calibration out of the long-lived browser request.
  The server now starts one background calibration per administrator, immediately acknowledges it,
  and exposes short status checks with model-loading and measurement progress. A slow NAS can load
  the model and measure all 20 representative chunks without DSM's reverse proxy returning 504.
- Package revision 10 permits the bounded `*.aws.cdn.hf.co` hostname family currently used by
  Hugging Face for regional model delivery. It still requires HTTPS and rejects suffix look-alike
  domains, allowing revision 9's checksum-verified model installation to follow the official
  `huggingface.co` redirect successfully.
- Package revision 9 replaces the misleading "included model" setup action with a resumable,
  checksum-verified Qwen model installation and visible byte/percentage progress. The embedding
  worker now starts before model acquisition and loads the model on first use, so a fresh setup can
  proceed directly from model installation to calibration without restarting the package. Step 6
  also returns actionable model, worker, token-limit, and calibration failures instead of a generic
  internal error.
- Package revision 8 generates idempotency keys with Web Crypto random bytes when
  `crypto.randomUUID()` is unavailable on a plain HTTP NAS address, with a final compatibility
  fallback for older browsers. Storage setup and every other protected mutation can therefore be
  submitted through `http://<ip address>/noderag/`.
- Package revision 7 displays the local access pattern `http://<ip address>/noderag/` directly in
  the Package Center description. This is a metadata-only addition on top of all revision 6 fixes.
- Package revision 6 replaces the Docker-only first-run storage default with NodeRag's DSM-owned
  package path. Existing Synology shared folders retain their ACL and mode; the probe creates and
  saves a dedicated `.noderag-managed` child, verifies write/fsync/rename/read there, and reports
  permission, path, filesystem, encryption, capacity, and durable-read failures separately.
- Package revision 5 displays a selectable one-time setup key in DSM's fresh-install wizard and
  displays an existing unconsumed key during upgrade. The key is installed with owner-only
  permissions, expires after first startup, and is removed after setup is complete.
- The DSM reverse proxy now forwards the original host and protocol, while NodeRag accepts those
  headers only from its loopback proxy. Administrator sessions and CSRF checks therefore work at
  both the NAS address and an HTTPS hostname such as `https://vanweb.synology.me/noderag/`.
- Package revision 4 serves frontend assets, API requests, setup events, PDFs, and downloads
  relative to the active Web Station mount. The DSM `/noderag/` alias no longer returns an empty
  application after the HTML shell loads.
- Package revision 3 no longer assumes DSM has created permanent package paths during `preinst`.
  Installation failures are written to DSM's package message file, and post-install preparation
  reports progress while validating storage and the bundled PostgreSQL runtime.
- Package revision 2 reduces `conf/privilege` to DSM's unambiguous
  `defaults.run-as=package` form. It contains no root action, capability, setuid/setgid request,
  or partial per-action override, and DSM creates the dedicated `noderag` internal identity.
- DSM package validation now uses the complete required lifecycle-script set, the DSM 7 64-pixel
  primary icon, standard root archive member names and permissions, and an INFO checksum for the
  payload.
- The reverse-proxy resource now uses DSM's required `proxy_target` field, declares WebStation as a
  dependency, and installs the desktop application config, firewall description, and complete icon
  set inside `package.tgz` where DSM expects them.
- The production launcher now supplies the bundled `pg_dump` path to both API and worker recovery
  runtimes, so packaged backups do not depend on a host executable search path.
- Full backups now exclude only transient rebuild relations that are both strictly named and owned
  by recorded NodeRag build state; unreferenced lookalike tables still fail classification closed.
- Restore activation clears non-active rebuild staging/rollback references and fails interrupted
  build/cleanup work for explicit operator review instead of retaining unusable ephemeral state.
- Runtime, API, MCP, package metadata, OpenAPI, settings defaults, parser revisions, dependency
  lockfile, migration head, SBOM, notices, model manifest, and build recipe are frozen together.
- The exact SPK has a minimum 1-hour fail-closed soak runner with source schedules, backup,
  isolation, locator, restart, log, health, memory, storage, and Ollama recovery checks.

## Runtime baseline

- DSM target: x86_64, DSM 7.2 build 64570 or newer.
- Package dependencies: Synology `Node.js_v22` and `WebStation`.
- CI/test runtime: Node.js 22.22.0 and pnpm 11.25.0.
- Node 22 support was reviewed on 2026-09-04 against the official Node.js release schedule; its
  planned end-of-life is 2027-04-30.

## Upgrade and compatibility

The current testbed source uses forward-only migration head `000017_ingestion_log_window`. Always create and
independently verify a full backup before upgrade. A PostgreSQL-major change is never an in-place
binary swap: use the documented logical dump, new-cluster restore, verification, activation, and
retained-source rollback procedure.

## Known release boundary

Docker/WSL qualification cannot prove Package Center variables, DSM package-account ACLs, the
Synology Node/C++ ABI, real `/volumeN` behavior, Hyper Backup integration, DSM reboot ordering,
NAS thermals, or file-sharing responsiveness. Those remain release blockers in the final DSM
checklist. A DSM failure requires a new release candidate; it must not be waived into `v1.0.0`.
